# 水池重置简化说明

更新日期：2026-10-29

本说明是最新执行口径。此前新增的活动链跟踪、处理中请求登记、旧局作废索引及SQL重置任务已撤回；默认方案、代理专属配置和水池合并组功能保留。

## 当前流程

1. 手动点击立即重置或周期到期，web-api 发布 resetPool 消息。
2. lottery 收到消息后，先清内存中各代理水池的有效投注、打码、赔付／预占、税收累计，清除待写回标记及水池缓存映射。
3. 随后删除 Redis 中以下四个 key：
   - fg_agent_effect_data
   - fg_agent_chips_data
   - fg_agent_profitLoss_data
   - fg_agent_revenue_data
4. 正常记录 pool_counters_reset 日志；Redis删除失败则记录错误。

这是全量水池重置，覆盖内存中已有的各代理以及Redis四个累计集合中的残留成员。先清内存，再删Redis；不等待旧局结算，不扫描会话，不建立重置任务或新的Redis跟踪记录。空消息及旧版消息也可以触发重置，批次号只作为可选的日志关联信息。

## 保留内容

- 默认合并方案、代理专属配置和实际分组关系。
- 各组初始配置及Base；累计清零后余额按Base重新开始。
- 玩家钱包、玩家独立统计、历史注单、流水和原业务对局记录。
- lottery:reservation_ledger 等不在上述四类累计中的其他key。

不再因为本次重置把旧局标记为失效，也不另行拦截迟到结算；之后的业务请求继续遵循原来的业务处理规则。

## 已移除的附加机制

- 不再创建或读取 sessions、inflight、reset_rounds 来决定是否重置。
- 不再创建附加的 seen 请求跟踪记录，不在启动时重建活动链。
- 不再使用LastResetID／PoolResetID、旧局作废索引或重置专用Redis锁。
- 不再为重置创建SQL任务。历史kind=reset记录保留，但从配置任务执行及阻塞判断中排除，不会一直等待或挡住新配置。

Luck5不做重复扣款／派奖判断，附加seen机制也不使用。为兼容既有Settle协议，只保留未结算局的原下注、预占和原池参数，结算完成即删除，不保存已完成防重结果。普通资金请求及分组配置已有并发控制保留，重置入口只使用本地缓存互斥保护。详见[Luck5结算实现说明](Luck5结算简化说明.md)。

## 验证与部署

- 自动化验证内存先清、四个Redis key删除、旧缓存快照不恢复原累计。
- 验证初始配置、玩家钱包、独立玩家统计、原对局和其他Redis数据不变。
- 验证空消息不依赖批次号或MySQL即可重置，以及Redis失败时报告错误并释放本地锁。
- 验证手动立即发送消息、周期未到不发送，以及发布失败不推进排期。
- 全项目Go测试、42项前端测试及前端生产构建已通过，构建仍有原有资源包体积告警。

升级全部web-api和lottery实例，避免旧实例继续写跟踪数据或运行旧重置逻辑。过去留下的辅助Redis key本次不会自动删除，但新代码不再使用或追加；如需物理清理，应在所有旧实例停止后另行做一次清理。

当前未部署，也未操作现场Redis。实际接收和执行情况以lottery日志为准；web-api发送成功不代表所有实例已经收到。
