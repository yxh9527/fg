## 一、使用方式

进入“控制管理 → 水池合并配置”，默认显示“默认合并方案”。顶部原有的单代理筛选不决定该页签的下发对象。

1. 默认选择“全部站点全部代理”；也可明确选择某个站点。已保存的默认方案范围不能交叉覆盖。
2. 新增、编辑、删除分组先修改草稿，列表显示“新增待发布／修改待发布／已发布”。默认方案按完整列表发布，无需勾选组；点击“预检查并发布”后，先核对弹窗中的全部组名称、成员游戏和配置来源，再查看代理应用检查，最后点击“发布完整方案（N组）并同步”。
3. 已跟随默认的代理按新版本同步，后续新增代理自动初始化。专属代理保留自己的完整配置。
4. “指定代理处理”支持跨页多选、按名称和模式筛选。可修改专属分组、保留现状为专属或恢复最新默认方案。
5. 编辑或删除专属组时，从第一个选中代理的生效配置选择组标识；其他代理没有对应组时会单独报告冲突，不靠名称匹配。
6. 预检查列出每个选中代理的结果；提交按钮只包含检查通过的代理。提交时重新校验版本，检查之后产生的冲突记录到批次明细。
7. “查看”展示单个代理实际生效组及余额，正式代理的旧编辑入口只读。测试代理 ID `0` 保留独立管理页，不自动包含在全量范围中。

没有合并组也可以发布，表示默认规则要求独立水池；专属代理不受该空默认方案覆盖。

例如列表有 `test2` 和新建的 `1111`，发布弹窗会同时展示这两个组；下方 `test3` 等行是目标代理，不是供选择的水池组。预检查和最终发布使用同一份草稿快照，翻页或后续编辑不会悄悄替换本次发布内容。被移除的组单独列出，空方案发布也明确提示恢复独立水池。代理预检查除组数量外，还返回当前组名称和发布目标组名称，避免“当前2组，目标2组”掩盖实际修改。

“预检查指定代理”需要先在表格中勾选代理。名称搜索不等于选择；站点、名称和配置模式筛选共同生效。查询为空时可点击“清除筛选”恢复全部正式代理；接口失败会显示加载错误及重试入口。按钮下方显示具体禁用原因，修改成员时游戏列表失败可单独重试；恢复默认、保留现状和删除组不受前端游戏列表加载失败影响。

代理表格左侧支持复选，右侧每行也提供“选择／取消选择”按钮，两种入口同步更新执行对象。代理表格在页签切换时保留独立实例，避免普通分组表格被复用后选择列丢失；刷新、跨页和返回页签时保留已选代理。

测试代理 ID `0` 不在正式代理表格内。可点击“管理测试代理（ID 0）”快捷入口；已填写的新增组名称及游戏顺序会带入测试代理弹窗，需要核对后手动提交。选择正式代理不会清空已填写的新增组草稿。

## 二、任务机制

2026-10-29 重置规则调整：手动入口立即派发清空任务，周期到期走同一执行逻辑；不再等待活动局或待核实请求结束。重置保留分组和初始配置，清空运行累计及旧活动标记，旧局后续请求失效。分组配置同步的等待规则不变。

- `web-api` 启动时检查迁移，并启动每两秒执行一轮的持久化同步调度器。多实例通过数据库行锁协调。
- 默认发布批次记录发布时范围内正式代理的最大 ID，按每页 100 个派发并保存游标。后续新增代理由注册任务接入，不扩张旧发布批次的范围快照。
- 代理创建和初始化绑定、任务保存处于同一数据库事务。周期巡检补齐绑定、落后版本和缺少的任务明细。
- 代理绑定分别记录期望模式、实际生效模式、期望版本和实际版本，实际任务确认前不提前显示生效。
- 每个代理使用一项 `layout` 执行任务切换完整分组，支持跨组移动；已有可复用组保留 ID、初始配置快照和余额。
- 只有变动组的相关游戏进入结算等待门禁，未变化组不额外暂停。新代理初始化完成前，目标方案涉及的游戏通过持久化状态限制新请求；续局及结算保留原处理方式。
- Redis 归属切换与旧独立池清理仍通过现有原子脚本执行；SQL 最终确认分组和映射。重复操作编号不再次清池。
- 默认方案来源游戏在创建逻辑组时固定。移除来源成员后，已有实际组保留原配置；后续新代理仍读取方案保存的来源游戏在该代理下的有效配置。
- 未开始的旧目标由新目标替代；已生成执行任务的旧目标先恢复完成，再收敛到最新目标。旧目标完成不能将新目标错误标记为已生效。

## 四、管理接口

接口前缀为 `/api/auth/v2/govern/pool-schemes`，沿用后台 M 账号权限和现有鉴权方式。

| 方法 | 相对路径 | 用途 |
| --- | --- | --- |
| GET | `/` | 指定范围的当前方案及已保存范围列表 |
| GET | `/games` | 不依赖某个代理的分组候选游戏 |
| POST | `/preview` | 默认方案预检查，支持分页 |
| POST | `/publish` | 发布新的默认版本并建立批次 |
| GET | `/agents` | 分页代理、跟随模式、版本及状态 |
| GET | `/agent` | 代理生效分组和目标分组 |
| POST | `/agents/preview` | 指定代理操作预检查 |
| POST | `/agents/submit` | 指定代理专属修改、保留现状或恢复默认 |
| GET | `/batches` | 分页批次及状态数量 |
| GET | `/batch` | 分页批次代理明细 |
| POST | `/retry` | 重试该批次失败项，不重置成功项 |

默认发布请求包含 `scope`（`all` 或 `site`）、`webId`、`version`、`groups` 和 `requestId`。每组包含 `key`、`name`、`symbols` 和 `sourceSymbol`。全部站点明确使用 `scope=all, webId=0`；指定站点使用正数站点 ID。这里的 `webId=0` 与测试代理 `agentId=0` 含义不同。

指定代理请求包含 `agentIds`、`action`（`custom`、`restore`、`keep`）、`requestId` 以及预检查返回的 `expected` 代理版本映射。专属分组操作另带 `kind`（`create`、`update`、`delete`）和 `group`。

同内容重试复用请求编号；不同内容不能复用编号。旧单代理写接口不会把缺少代理 ID 解释为全量操作；正式代理写入返回新入口提示，测试代理保留原语义。

## 五、自动化验证与边界

已执行上述八个 Go 模块的完整测试及前端生产构建，均通过。完整发布预览修正后，前端水池相关测试扩展为 42 项并通过，其中包含真实浏览器回归：切换页签后选择框可见，复选与行内按钮可实际选中，刷新、跨页和返回页签后保留选择，选中代理后预检查能够触发；新建 `1111` 后，预检弹窗展示其名称、成员及完整方案组数，点击发布携带全部组，发布后状态更新为已发布。构建仅出现原有资源包体积告警。

浏览器回归自动查找 Chrome 或 Edge，也可通过 `CHROME_BIN` 指定浏览器可执行文件；未安装浏览器的环境会明确跳过该项。

后端新增测试使用纯 Go SQLite 内存数据库及 miniredis，覆盖实际事务、版本与任务落库、归属应用和最终确认；不连接生产数据库。

- 现有代理全量应用与新增代理事务初始化。
- 各代理独立初始配置和余额，专属配置保留及恢复最新默认。
- 来源成员移除后新代理仍使用保存的来源规则。
- 历史配置匹配时无重建接入，差异时等待明确选择。
- 跨组移动保留组身份和余额，重复任务不再次清池。
- 发布请求幂等、范围重叠拒绝、过期预检查不覆盖新配置。
- 同组数量下预检查仍展示组名称变化，发布后 `1111` 及成员变更实际生效并保留原组 ID；预检查本身不改变生效配置。
- 初始化任务失败时回滚部分组，保持限制并支持恢复。
- 新旧目标收敛、缺失任务补偿及无关组门禁隔离。
- 页面范围选择、草稿顺序、旧响应隔离、预检查快照和重试编号。

## 六、上线与历史接入

1. 升级前备份配置和运行数据，在测试环境验证新表迁移和注册事务。
2. 按原有升级维护流程完成存量活动订单处理，升级全部 `web-api` 和 `lottery` 实例，再开放方案入口；旧执行器不认识 `layout` 任务，不能混跑。
3. 默认方案首次发布时，一致的已有配置直接建立映射，保留实际组和余额；不同配置显示待接入确认，由管理员选择保留专属或恢复默认。
4. 首次发布优先检查预览和代理明细，再逐步扩大范围。失败、等待和冲突不能视为已生效。
5. 调度器位于 `web-api`，实际切换位于 `lottery`；两者都需正常运行。任一服务暂时不可用时，持久化任务保留并继续显示未完成。

本次没有执行真实迁移、发布方案、修改线上代理或部署服务。
